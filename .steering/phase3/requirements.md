# Phase 3: レイヤーシステム — 要求定義

## 概要

Phase 2 で確立したフレームワーク API の上に、複数レイヤーの切り替え機構を実装する。
キーボードの 12 キー（3x4）という物理的制約を、レイヤーの重ね合わせで論理的に拡張し、
数字・記号・ファンクションキーなど多彩なキー入力を可能にする。

---

## 変更・追加する機能

### 1. 複数レイヤーキーマップ

- 最大レイヤー数を定数で定義する（初期値: 4）
- `Keymap` 構造体を単一レイヤー（`Layer0`）から複数レイヤー対応に変更する
- レイヤー 0 は常にベースレイヤーとして存在する

### 2. レイヤー操作キー

| キー | 動作 |
|------|------|
| **MO(n)** | ホールド中のみレイヤー n を有効にする。リリースで元に戻る |
| **TG(n)** | 押下のたびにレイヤー n を ON/OFF トグルする |

### 3. 透過キー（KC_TRNS）

- レイヤー上で `KC_TRNS` が割り当てられたキーは、下のレイヤーのキーコードを参照する
- レイヤー 0 まで遡っても `KC_TRNS` の場合は `None`（無操作）として扱う

### 4. タップ検出キー

| キー | 動作 |
|------|------|
| **TT(n)** | タップで通常キーコード送信。ホールドで MO(n) として動作 |
| **LT(n, kc)** | タップでキーコード kc を送信。ホールドでレイヤー n を有効にする |

- タップ/ホールドの判定閾値を定数で定義する（初期値: 200ms）

---

## ユーザーストーリー

### US-01: レイヤーを切り替えられる

> キーボードビルダーとして、MO キーを押している間だけ別レイヤーが有効になることで、
> 12 キーの物理キーボードでも数字・記号・ファンクションキーを入力したい。

**受け入れ条件:**
- MO(1) を押している間、レイヤー 1 のキーマップが有効になる
- MO(1) を離すとレイヤー 0 に戻る
- MO 押下中に別キーを押すとレイヤー 1 のキーコードが送信される

### US-02: レイヤーをトグルできる

> キーボードビルダーとして、TG キーを押すたびにレイヤーが切り替わることで、
> 長時間レイヤーキーを押し続けなくても別レイヤーを使い続けたい。

**受け入れ条件:**
- TG(1) を 1 回押すとレイヤー 1 が有効になる
- もう 1 回 TG(1) を押すとレイヤー 1 が無効になりレイヤー 0 に戻る

### US-03: 透過キーが機能する

> キーボードビルダーとして、上位レイヤーで一部のキーだけ変更し残りは下のレイヤーを
> そのまま使いたい。

**受け入れ条件:**
- レイヤー 1 で `KC_TRNS` が割り当てられたキーを押すと、レイヤー 0 のキーコードが送信される
- 全レイヤーが `KC_TRNS` の場合は何も送信されない

### US-04: タップとホールドで動作が変わる

> キーボードビルダーとして、LT キーを短く押すと通常キーとして動作し、
> 長押しするとレイヤー切り替えとして動作することで、キー数を節約したい。

**受け入れ条件:**
- LT(1, A) を短く押す（< 200ms）と "A" が入力される
- LT(1, A) を長押しする（>= 200ms）とレイヤー 1 が有効になる
- TT(1) はタップでキーコード送信、ホールドで MO(1) として動作する

## 制約事項

### TinyGo 制約（必須遵守）

- ホットパス（スキャンループ内）でヒープ割り当て禁止
- レイヤー状態は固定サイズ配列で管理する（動的配列不可）
- `reflect` / `fmt.Sprintf` / `fmt.Printf` 使用禁止
- goroutine 追加なし（メインループ 1 goroutine）

### パフォーマンス制約

- スキャンループ周期 1ms を維持する
- レイヤー解決のオーバーヘッドがスキャンサイクルに影響しないこと
- RAM 使用量 128KB 以下を維持する

### 設計制約

- `machine` 非依存のレイヤーロジックにはユニットテストを書く
- パッケージ間の循環依存を発生させない
- Phase 2 の公開 API との後方互換性を維持する（`Config` / `Run()` の使い方を変えない）
- `keycode.Keycode` の既存エンコーディング（0x0000 / 0xE0xx / 0xF0xx）と互換性を保つ

### スコープ外

- Composite HID（Phase 5）
- マクロ / コンボ（Phase 7）
- NKRO（Phase 7）
- Flash 永続化（Phase 7）
- 周辺機器（encoder / LED / OLED）は Phase 4
