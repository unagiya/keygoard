# 用語集

> **UI/UX 用語について:** 本プロジェクトはファームウェアであり GUI を持たない。
> OLED ディスプレイ（Phase 3 以降）が追加された時点でこのセクションを設ける。

## ドメイン用語の定義

キーボードファームウェア固有の用語を定義する。

### マトリクス関連

| 用語 | 定義 |
|---|---|
| **マトリクス（Matrix）** | キースイッチが格子状（行 × 列）に配線されたキーボードの電気的構造。直接配線より少ない GPIO で多数のキーを読み取れる |
| **COL2ROW** | マトリクススキャンの方式の一種。列（Col）ピンを 1 本ずつ High にして、全行（Row）ピンを読み取る。本プロジェクトで採用 |
| **ROW2COL** | COL2ROW の逆。行を High にして列を読み取る方式。本プロジェクトでは未使用 |
| **スキャン（Scan）** | マトリクスの全キーの押下状態を 1 サイクルで読み取る処理 |
| **スキャンサイクル** | スキャンを 1 回実行する単位。本プロジェクトでは 1ms 周期で実行する |
| **デバウンス（Debounce）** | キースイッチの接触ノイズ（チャタリング）を除去する処理。連続 N サイクル同じ状態が続いたときに状態を確定する |
| **チャタリング（Chattering）** | キースイッチの物理的な接触時に発生する短期間の電気的ノイズ。押下・解放を繰り返すように見える誤信号 |
| **デバウンス閾値（Debounce Threshold）** | 状態確定に必要な連続同一読み取り回数。本プロジェクトでは 5 サイクル（= 5ms） |
| **ホットパス（Hot Path）** | スキャンループ内の毎サイクル実行されるコードパス。ヒープ割り当て禁止 |

### キーコード・キーマップ関連

| 用語 | 定義 |
|---|---|
| **キーコード（Keycode）** | 物理キーに割り当てられた HID Usage ID ベースの識別子。`keycode.Keycode` 型（`uint16`）で表現する |
| **HID Usage ID** | USB HID 規格で定義されたキーの識別番号。Usage Page 7（Keyboard/Keypad）を使用する |
| **修飾キー（Modifier Key）** | Ctrl / Shift / Alt / GUI（Command / Win）の総称。キーコードは `0xE000` 台 |
| **キーマップ（Keymap）** | 物理キーの位置（row, col）と送信するキーコードの対応表 |
| **レイヤー（Layer）** | キーマップの重ね合わせ概念。複数のキー割り当てを切り替えて 1 つのキーボードに複数の役割を持たせる |
| **レイヤー 0（Layer 0）** | デフォルトの最下位レイヤー。Phase 1 ではこのレイヤーのみ実装する |
| **MO（Momentary）** | ホールド中のみ指定レイヤーを有効にするレイヤー操作キー（Phase 2 以降） |
| **TG（Toggle）** | 押下のたびに指定レイヤーを ON/OFF するレイヤー操作キー（Phase 2 以降） |
| **TT（Tap-Toggle）** | タップ回数でレイヤーをトグルし、ホールドで MO として動作するキー（Phase 2 以降） |
| **LT（Layer Tap）** | タップで通常キーコードを送信し、ホールドでレイヤー切り替えを行うキー（Phase 2 以降） |
| **KC_TRNS（Transparent）** | 現在のレイヤーに割り当てなし（透過）を表すキーコード。下のレイヤーの割り当てを参照する（Phase 2 以降） |

### USB / HID 関連

| 用語 | 定義 |
|---|---|
| **HID（Human Interface Device）** | USB キーボード・マウス等の入力デバイスに使われる USB の標準プロトコル |
| **USB エニュメレーション（USB Enumeration）** | USB デバイスを接続した際に OS がデバイスを認識・設定する過程。完了まで数百 ms かかる |
| **HID レポート（HID Report）** | キーボードが OS に送信するデータパケット。本プロジェクトでは 8 バイト固定長 |
| **6KRO（6-Key Rollover）** | 同時押しを最大 6 キーまで認識できる方式。本プロジェクトの Phase 1〜3 で採用 |
| **NKRO（N-Key Rollover）** | すべてのキーの同時押しを認識できる方式（Phase 6 で実装予定） |
| **Composite HID** | キーボードとゲームパッドなど複数の HID デバイスを 1 つの USB デバイスとして組み合わせる方式（Phase 4 で実装予定） |
| **HID 記述子（HID Descriptor）** | HID デバイスの能力を OS に伝えるバイト列。本プロジェクトでは TinyGo 標準の `machine/usb/hid` を使い自前実装しない |

### ハードウェア関連

| 用語 | 定義 |
|---|---|
| **RP2040** | Raspberry Pi 財団が開発したマイクロコントローラ。本プロジェクトのターゲット MCU |
| **MCU（Microcontroller Unit）** | マイクロコントローラ。CPU・メモリ・周辺機能を 1 チップに統合した半導体 |
| **GPIO（General Purpose Input/Output）** | MCU の汎用入出力ピン。マトリクスのスキャンに使用する |
| **プルダウン（Pull-down）** | 入力ピンを抵抗でグラウンドに接続し、未接続時のデフォルト電位を Low（0）に保つ設定 |
| **zero-kb02** | 本プロジェクトのテスト実機。sago35 氏設計の RP2040 ベース自作キーボード |
| **エンコーダー（Encoder）** | ロータリーエンコーダー。回転操作を A/B 信号として出力する入力デバイス（Phase 3 以降） |
| **WS2812 / SK6812** | プログラマブル RGB LED。1 本の信号線で色・輝度を制御できる（Phase 3 以降） |
| **SSD1306** | I2C 接続の OLED ディスプレイドライバ IC（Phase 3 以降） |
| **フラッシュ（Flash）** | MCU 内蔵の不揮発性メモリ。キーマップや設定の永続化に使用する（Phase 6 以降） |
| **リアクティブライティング（Reactive Lighting）** | キー押下時に対応する LED を点灯させるエフェクト。マトリクス位置と LED インデックスのマッピングが必要（Phase 7 以降） |
| **OLED 自由描画** | OLED ディスプレイに任意のテキストやカスタム画像を描画する機能（Phase 7 以降） |

## ビジネス用語の定義

プロジェクト運営・開発プロセス上の用語を定義する。

| 用語 | 定義 |
|---|---|
| **Phase（フェーズ）** | 開発工程の区切り単位。実機確認が完了して初めてフェーズ完了とする |
| **チェックポイント（Checkpoint）** | フェーズ内の開発途中における動作確認済みの節目。`v0.(N-1).x` タグで記録する |
| **マイルストーン（Milestone）** | フェーズ完了の節目。実機確認後 `main` にマージし `v0.N.0` タグを打つ |
| **スペック駆動開発** | 実装前に `.steering/` 配下の仕様書（requirements / design / tasklist）を書き、仕様を確定してから実装を進める開発手法 |
| **実機確認** | ファームウェアを実際のハードウェアに書き込んで動作を検証する工程。各フェーズ完了の必須条件 |
| **feature ブランチ** | 1 つの機能に対応するトピックブランチ（例: `feature/matrix-scan`） |
| **フレームワーク（Framework）** | 本プロジェクトの提供形態。ボード固有の設定（ピン配置・キーマップ）を `examples/` に置き、コアロジックを再利用可能なパッケージとして提供する |

## コード上の命名規則

コードに登場する主要な識別子とその意味。詳細は [development-guidelines.md](development-guidelines.md) を参照。

### 型・構造体

| 識別子 | パッケージ | 意味 |
|---|---|---|
| `Keycode` | `keycode` | HID キーコードを表す型（`uint16`） |
| `Keyboard` | `engine` | エンジン最上位の構造体。スキャン・キーマップ解決・HID 送信を統合する |
| `Keymap` | `engine` | レイヤー 0 のキー割り当てを保持する構造体 |
| `Scanner` | `matrix` | COL2ROW マトリクススキャナーの構造体 |
| `Debouncer` | `matrix` | キーごとのデバウンス状態を保持する構造体 |

### メソッド・関数

| 識別子 | 意味 |
|---|---|
| `Init()` | ハードウェアを初期化する。USB エニュメレーション待機を含む |
| `Tick()` | 1 スキャンサイクルを実行する。メインループから毎回呼び出す |
| `Scan()` | マトリクスを 1 回スキャンし、デバウンス後の状態と変化フラグを返す |
| `Update()` | 生スキャン結果をデバウンスに通し、確定状態を更新する |
| `Down()` | キーを押下として HID レポートに登録する |
| `Up()` | キーを解放として HID レポートから除去する |

### 定数・変数

| 識別子 | パッケージ | 意味 |
|---|---|---|
| `RowCount` | `matrix` | マトリクスの行数（3） |
| `ColCount` | `matrix` | マトリクスの列数（4） |
| `debounceThr` | `matrix` | デバウンス確定閾値（5 サイクル、非公開） |
| `None` | `keycode` | キー未割り当てを表す定数（`0x0000`） |
| `ModLeftCtrl` … | `keycode` | 修飾キー定数（`0xE000` 台） |
| `A` … `Z`, `F1` … | `keycode` | 通常キー定数（`0xF000` 台） |
| `ErrKeyOverflow` | `engine` | 6KRO 上限超過エラー |
| `Layer0` | `engine.Keymap` | レイヤー 0 のキー割り当て配列 |
